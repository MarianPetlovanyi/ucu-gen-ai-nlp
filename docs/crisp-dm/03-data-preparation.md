## Formatting for the models
- **LLM input**: the contract as numbered spans, `[id] text` with whitespace collapsed, plus the 17 hypotheses
  (`nli.format_contract`). Span ids are the only way to cite evidence, so citations can be validated and
  hallucinated quotes are impossible by construction.
- **Encoders**: span text truncated to 256 tokens (bge-small for retrieval, DeBERTa for the NLI baselines).
- For dataset contracts the eval uses the **gold spans** (oracle segmentation), so C3/C4 are measured without C2
  errors. The app and the end-to-end checks use C1 → C2 output instead.

## Segmentation conventions measured on train (input to C2)
ContractNLI spans come from the dataset authors' own splitter. To reproduce its conventions, we measured on train:
- every line break is a span boundary (18 052 of 18 052);
- inline enumerations `(a)`, `(ii)`, `(3)` start a new span, even after words like "that" or "of";
- a bare multi-level section number at the start of a line (`2.1 The Recipient…`) is its own span in 62% of
  1 117 cases, so C2 cuts there as well.

## Annotation conventions verified on train (input to the C4 prompt)
Error analysis of C4 (phase 5) showed that most errors were disagreements about *how to read* a hypothesis.
Each convention in prompt `nli_v3` was checked against **train** label counts before it was adopted, never
against dev:

| Hypothesis | Pattern in the contract | Train labels | Convention in the prompt |
|---|---|---|---|
| nda-1 explicit identification | "whether or not marked / designated" | C 31 · E 1 · N 1 | Contradiction only with an explicit statement like this |
| nda-1 | broad definition, nothing about marking | N 211 · E 43 · C 33 | NotMentioned |
| nda-16 return/destroy **upon termination** | return only "at any time upon request" | N 150 · E 69 | NotMentioned unless linked to termination |
| nda-16 | return linked to termination/expiry | E 92 · N 13 · C 1 | Entailment |
| nda-20 retain after return | "return/destroy all … copies", no retention exception | C 127 · E 16 · N 5 | Contradiction |
| nda-20 | return-all plus a retention/backup exception | E 56 · C 3 · N 1 | Entailment |

The same heuristics on **dev** show a different picture for nda-20: "return all copies, no exception" is
Contradiction in only 6 of 22 dev contracts (15 NotMentioned). The annotators were inconsistent between splits.
We keep the train convention and report the drift in phase 5. We did not tune the prompt to dev.

A rule written in prompt v2 from a single dev example (nda-16 "on request counts") turned out to be wrong on
train (150 vs 69) and was reverted in v3. The lesson for the agent instructions: annotation conventions must be
checked against train counts.
